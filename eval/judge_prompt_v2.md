# 判卷标准：按事实清单判（RAG 效果评测用，见 `eval/run_rag.py`）

只判**回答里陈述的事实对不对**。不看写法、详略、有没有引原文、有没有编号；但回答**说成是史书记载**的内容（引用的原话、"某传记载""史书说"），要核对是不是真的出自原文。

## 输入

每个包是一个 JSON 列表，每题有：
- 问题 `q`；
- gold 原文和白话（`gold`）；
- 出题时冻结的**事实清单**（`checklist`）和相关原文（`related`，源 id 列表）；
- 几份回答（`answers`，标签 g1 / g2 / … 是随机分配的，每题不同）。

回答来自不同的系统，有的查过资料，有的没有。不要猜来源，每份独立按清单判。回答在打包前已统一格式（去掉了 [n] 编号，引号换成同一种）。

## 事实清单

```
"checklist": {
  "must": [{"id": "m1", "text": "霍峻守城约一年", "core": true, "asked": true},
           {"id": "m2", "text": "霍峻手下只有数百人", "core": false, "asked": false}, ...],
  "must_not": [{"id": "x1", "text": "说城被攻破"}, ...]
}
```

- `must`：回答可能涉及的要点。`core: true` 是问题的核心；`asked: true` 是题目明确要求回答的（core 都是）；`asked: false` 是背景细节，题目没问，回答不写不扣分。
- `must_not`：常见的错误说法（混淆、演义当正史、同名的另一个人）。
- 有的 core 项带 `core_partial`，那是代码算判定用的，你照常标。

## 怎么标

对每份回答，逐项标：
- **must 每项**：
  - `yes`：答到了，**意思**和要点一致。措辞、详略不管，换了说法、概括了、没有逐字照搬都算 yes；只看要点里的**关键信息**（人、事、结论、数字和年份）对不对，不因为没写全要点里的修饰性细节标 no。
  - `no`：没提到这个要点（背景细节项没写，照样标 no，代码不会因此扣分）。
  - `wrong`：提到了但说错了（年份、数字、人物、谁做了什么和原文不符）。
  - `hedged`：只说不确定、不知道，没有给出明确说法。如果是"不确定，可能是 X"，按 X 判 yes / wrong，另在 `hedges` 里记一条。
- **must_not 每项**：`yes`（回答里出现了这个错误说法）或 `no`。
- **编造的史料**（`fabricated`）：回答里**每一句**说成是史书原文或史书记载的内容都要核对，包括引号里的原话，以及"据某传""《三国志》记载""裴注引某书说""史载"这类说法：
  - 在原文里找不到，或者和原文不符（话是编的、张冠李戴到别人或别的书上、原文没有这件事），记一条：写清回答说了什么、你查了哪些词、原文实际是什么（给源 id）。
  - 话的**大意**和原文一致、只是措辞不同，不算编造。
  - 回答自己标明是推测、传说、演义说法、后人评价的，不算编造。
- **清单以外的事实错误**（`extra_errors`）：回答里清单没涉及、和原文矛盾的具体事实（年份、人名、官职、谁做了什么）。每条一句，写清回答说了什么、原文是什么（给源 id）。已经记进 `fabricated` 的不再重复记。
- **查不到的确定说法**（`unsupported`）：清单以外、在原文里查不到、说得很确定，但**没有说成是史书记载**的具体事实。查了哪些词没找到要写清楚。
- 核对用原文（可以先看 `related`）：
  - `uv run python -m eval.find 词1 词2` 找词，列出源 id；
  - `uv run python -m eval.find --id 源id` 看全文。

  原文是繁体，查词时用繁体更容易命中。不联网，不凭记忆裁定史实。
- 官职职能、今天的地名这类原文没有的点，按清单的要点判（清单写的就是参考答案）。

## 判定由代码算，不用你写

- **错**：有 core 项是 no / wrong / hedged（带 `core_partial` 的只是 no / hedged 时除外），或 must_not 里有 yes。
- **部分**：不是错，但有下面任何一种：
  - `asked` 的非 core 项是 no / wrong / hedged；
  - 带 `core_partial` 的 core 项是 no / hedged；
  - 背景细节项（`asked: false`）是 wrong；
  - `fabricated` 或 `extra_errors` 不是空的。
- **对**：其余。
- `unsupported` 只记录，不改判定。

## 输出

每个包写一个同名的 `batchNN.out.jsonl`，一份回答一行（Python `json.dumps(..., ensure_ascii=False)`）：

```
{"model": "g2", "qid": "h-01",
 "must": {"m1": "yes", "m2": "wrong"}, "must_not": {"x1": "no"},
 "fabricated": ["说《霍峻传》记他 '城可破, 头不可得', 查 '頭' '城' 只有 41-0000 '小人頭可得, 城不可得'"],
 "extra_errors": [], "unsupported": [], "hedges": [],
 "refused": false, "comment": "一句话", "uncertain": ""}
```

- `refused`：有答案的题，回答整体拒答（说查不到、不知道，没有给出任何要点）。
- `uncertain`：真拿不准某一项怎么标时，写一句原因，会交给出题人裁决。先按你的最佳判断标。

包里每个 (qid, model) 都要有且只有一行。写完用一小段 Python 核对行数和回答数一致，并核对每行的 must / must_not 的键和清单一致。
