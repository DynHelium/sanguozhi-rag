# 设计说明

## 流水线

```
离线（数据准备）
  维基文库 wikitext ── ingest.fetch_wikisource（按 revid）
    → ingest.sanguozhi：解析正文与裴注，套用 patches.yaml，得到段落 + 裴注（源 id 如 01-0004、01-0004n1）
    → rag.chunk：切块（正文、裴注各自成块，裴注指回所注正文）
    → 白话译文（逐段/逐条，按源 id 对齐）→ ingest.trans_chunks：白话检索切块
    → rag.dense：bge-m3 向量缓存；rag.bm25：字 bigram 倒排
    → 别名表 data/aliases.json、年号表 data/eras.json（每条带出处）

在线（回答一个问题）
  用户问题
    → agent 循环（OpenAI 标准 tools）：模型自己决定调用
         search(query, book?, part?)  白话 hybrid 检索（BM25 + dense，RRF 融合；查询里的人名按别名表另加一路扩展查询；可限定哪一书、正文或裴注）
         read(chunk_id, …)    读前后文；读正文时附上它的裴注，读裴注时附上它注的正文
         who(name)            别名表查人：指谁、有几个同名、其他称呼
         era(era, year, …)    年号第几年 → 公元年
       轮数有上限：最后一轮不传 tools，要求直接作答
    → 循环里的代码介入：搜得太少就作答时提示再查（汇总题门槛更高）；回答说"没有记载"而搜得少或没读过传末的评时要求核实一次
    → 作答后的代码检查：坏回答（截断、只有工具标记）重答一次；按资料逐句自查一遍；英文问题得到中文回答时要求改写一次；
       「」里的引文逐字核对原文，对不上的回给模型改一次，改后仍对不上的标为未通过核验；
       引文只标了一个编号、且看过的资料里恰好只有一块含这段文字时，代码改正编号
    → 回答（带资料编号和出处）。先给结论、记载和推断用措辞区分，是 system prompt 的要求；代码只核对引文，
       不保证每个事实都有出处
```

## 关键决定及理由

| 决定 | 理由 |
|---|---|
| 两种大模型后端：DeepSeek V4.1 Flash（OpenAI 兼容接口，经 OpenRouter）和 Claude Haiku 5.5（Claude 原生接口，Anthropic SDK），由 `.env` 选 | 其余代码只调 `rag.llm.complete`，Claude 后端在这一处转换消息和响应。不用 Anthropic 的 OpenAI 兼容端点：那里思考档位被忽略、不支持缓存、对话中途的 system 消息会被挪到最前面 |
| 代码给模型的话（再查提示、自查、改引文、改写、游戏里的"猜错了"）一律用 developer 消息，不冒充用户；要模型改自己的回答时，把草稿放进这条消息，不作为 assistant 消息放回 | 用 user 角色时，模型把提示当成用户的追问，回答里写"我按您的要求重新核实了"。Claude 原生接口只允许对话中途的 system 消息跟在用户消息或工具结果后面，不能紧跟在模型的文字回答后面 |
| system prompt 写原则，不规定格式 | 写明什么算依据、推断怎么点明、说"没有记载"之前要核实；规定"事实 / 推断 / 背景"分段时，模型不管问题需不需要都会套用，读起来僵硬 |
| 英文问题里的拼音人名由代码先查表，不让模型猜 | 很多人名拼音相同（Zhou Tai 是周泰也是州泰；Liu Yan 有刘焉、刘琰、刘延）。`who` 接受拼音和威妥玛拼音，列出所有同音的人；其他史书和小说里的叫法（北宫伯玉、孙尚香）对应到《三国志》的写法（`data/aliases_extra.json`） |
| Embedding 用本地开源模型（bge-m3）并写死默认值 | 索引与 embedding 绑定；本地模型免 key、可复现 |
| 混合检索而非纯向量 | 人名、地名、官职是精确的词，纯向量会混淆曹操/曹丕/曹植 |
| 入库和查询都做繁→简，走同一套 `rag/normalize.py` | 原文是繁体，提问多为简体；两边不一致就对不上 |
| 别名表只用于查询侧扩展，不改索引 | 史书里称谓随卷而变（太祖、曹公、魏武），问"曹操"要能找到写"魏太祖"的段落；同名的人（几个马忠）不扩展。译文称谓忠于原文后，问"曹操""刘备"直接搜就搜不到。扩展后的查询另加一路融合，而不是替换原查询：替换会把原来排第一的块挤下去 |
| 裴注独立成块，用 parent 指回所注段落 | 1776 条裴注中 60 条超过 1000 字，最长一条 10209 字，并进正文会把块撑大，也分不清陈寿与裴注所引；读裴注时可以把所注正文一起交给模型 |
| 离线把全书译成白话，作为检索用的附加索引 | 一次解决三件事：白话提问对文言用词（去世/薨）、年号只写"七年"、后文只写名或字（"策""宫"）。译文单独建索引，不拼进原文块。**原文仍是依据**：展示和引文逐字校验用原文，prompt 要求引文只引原文、不引译文。48 道检索题上（BM25 + 向量 + 别名扩展，宽松口径）hit@10 从搜原文的 0.69 升到搜白话的 0.81，见 EVALUATION.md "检索" |
| 译文称谓忠于原文，只做现代化 | 太祖 → 魏太祖、權 → 孙权，先主照写；"谁是谁"交给别名表，不在译文里替换人名 |
| 年号换算由代码查表，不让模型凭记忆 | 建兴、甘露等同名年号蜀/吴/魏各不同；年号表从原文统计，并用参考表交叉核对 |
| 查询端去掉白话问句词（`rag/bm25.py` 的 QUESTION_WORDS） | 白话问句词在文言里很稀有（"是谁"全书 3 处），idf 反而很高，会把无关短文档顶上来。词表是照着检索评测题挑的，所以这套题算开发集 |
| 评测 gold 标源 id（段落 id / 裴注 id），不标 chunk id | 换切块策略 chunk id 会变，源 id 不变；同一套题可比较不同切法 |
| 搜什么、读什么由模型用工具决定，代码不预检索 | 模型能按资料里出现的人名、年号继续查（读前后文、查同名者），这是固定 k 块的 RAG 做不到的 |
| search 可以限定哪一书（魏 / 蜀 / 吴）和正文 / 裴注，筛选在每一路检索排名之前做 | 冷门人物常常只在某一卷的裴注里出现一次，全书检索时会被魏书、蜀书里更相关的段落挤出前几名；先取全书前 k 名再过滤也不行，目标块可能根本不在前 k 名里。只在模型已经确定范围时才填，不填就搜全书 |
| 给模型的工具优先选"不需要知识也能用"的 | 读前后文、读裴注所注正文、别名表查人、年号换算，都不依赖模型的史学知识 |
| 轮数上限由代码保证（最后一轮不传 tools） | 实测 `tool_choice="none"` 会被部分模型无视 |
| 作答后由代码做检查（自查、引文核对） | 判卷发现的主要错误是补了资料以外的背景、旁证张冠李戴、引文记错字；自查针对前两种，引文核对针对后一种。引文核对是确定性的代码检查，自查仍是一次模型请求，不保证改对 |
| 向量检索用 numpy 暴力算余弦，不用向量数据库 | 原文、白话两套各 4365 块，1024 维 float32 只有几十 MB，一次矩阵乘法毫秒级 |
| 仓库里只放白文，标点版由使用者下载 | 原文是公有领域，但维基文库录入的断句标点沿用中华书局点校本；`ingest.use_wikisource` 按 revid 下载，结果可复现 |

## 切块

切块的数据依据（`uv run python -m eval.length_stats` 可复现）：

- 正文段 2240 个：中位数 149 字，90% 分位 395，最长 2697；360 段不足 50 字，17 段超过 1000 字。
- 裴注 1776 条：中位数 112 字，90% 分位 496，最长 10209（卷02 獻帝傳 禅代众事）；60 条超过 1000 字。短注多是音注（如"橫音光"）。
- 按 。！？ 切句，最长的一句 398 字，所以 `max_len >= 400` 时不会遇到放不下的单句。
- 156 个段/注不以句末标点结尾，多是以"曰："结尾引出下一段（如 14-0043"曄議曰："）；也有"帝不听。"（22-0013）这种回应上一段的短段。
- 49 个段/注的 text 里含换行（来自多行的 quote 模板）。
- search 与 text 只差年号后的" NNN年"，句末标点完全一致（已全量核对），所以两者能用同一套句子边界切开。

## BM25

`rag/bm25.py` 按字 bigram 建倒排表（词 → {文档序号: 次数}），查询 q 对文档 d 的分数：

```
score(q, d) = Σ_{t ∈ q} idf(t) · tf · (k1 + 1) / (tf + k1 · (1 − b + b · dl / avgdl))
idf(t)      = ln(1 + (N − df + 0.5) / (df + 0.5))
```

tf 是词 t 在 d 里的次数，dl 是 d 的词数，avgdl 是平均词数，N 是文档总数，df 是含 t 的文档数。
k1 = 1.2（tf 饱和速度），b = 0.75（长度归一的程度）。idf 取 Lucene 的加 1 版本：原始 BM25 的 idf 在 df 超过一半时为负，
"之""曰"开头这类几乎每块都有的 bigram 会倒扣分。

## 话题限制

只靠 system prompt 要求模型只回答三国历史问题（演义情节不拒答，而是说明正史怎么记载），代码不强制。没有检索阈值或分类器闸门；
公网部署时可以考虑另加（见 DEPLOY.md）。

## 史料分级

见 `data/sources/README.md`。prompt 要求回答标明依据层级（陈寿正文 / 裴注引某书），史料互相矛盾时并列呈现。

## 评测

大模型的训练语料里本来就有大量三国内容，只看"答对没有"分不清是检索的功劳还是模型的记忆，所以分两层：检索层不经过大模型，
看 hit@k / MRR；回答层让同一个模型分几组回答同一批题（闭卷、检索一次、给出 gold 原文、只给工具、网页配置），前几组只差给什么资料，
按事实清单判卷。方法和结果见 [EVALUATION.md](EVALUATION.md)。

## 引文核对

`rag/quotes.py` 做两项纯代码的检查：回答里「」中的文字能不能在模型看过的原文块里逐字找到（繁简和标点的差别不算），以及引文后面的
`[n]` 是否指向含有这段文字的那一块。只有引文只标了一个编号、而且看过的块里恰好只有一块含这段文字时，代码才改正编号；其他情况只报告结果。
找不到的标为未通过核验，原因可能是记错字，也可能是异体字。这只覆盖引文本身，不能保证转述和解读正确。

## 海龟汤

"海龟汤"是一种推理游戏：给出一个离奇的情景（汤面），玩家只能问能用"是 / 不是"回答的问题，最后说出完整的来龙去脉（汤底）。
这里每道题都取自《三国志》，汤底挂着出处段落。题库 `data/soup/puzzles.jsonl` 分三档：有名的人（刘备、诸葛亮、曹操、关羽）、
不太有名的（张松、曹冲、诸葛亮的妻子）、最冷门的（卑弥呼、武宣卞皇后、曹节）。

- 裁判（`rag/soup.py`）只拿到这道题的汤底和出处原文，只答结论：是非题答是 / 不是，二选一答选项，无关紧要的细节答"不重要"，
  原文没写的答"没有记载"（不硬判真假），问法有歧义时按自己的理解答，并用几个字说明按哪种理解。不提供问题以外的信息。
- 玩家提交解释时，按汤底的必答要点逐条核对，全部答到、没有矛盾才算解开；没解开时只说答到了几点，不说缺哪几点。
- `uv run python -m eval.soup` 用每道题的标准问答测裁判的准确率。单独的页面：`uv run python -m app.soup`。

## 聊天里的游戏（skill）

聊天里可以玩猜人物和海龟汤（`rag/skills.py`、`rag/guess.py`、`rag/soup.py`）。

- **结构**：每个游戏是 `skills/<名>/SKILL.md`（frontmatter 写名字、说明、玩法选项和快捷命令，正文是玩法说明）加一个游戏类。
  游戏是问答 agent 的 skill：agent 的 system prompt 里有 skill 列表，tools 里有 `start_game(game, mode?)` 和 `end_game(reveal)`，
  对方说"来玩猜人物""你来猜我想的人""不玩了"时由 agent 决定开局或结束，不靠关键词匹配；handler 抛 `SkillReply`，
  开局说明由程序直接显示，不再请求模型。网页按钮发快捷命令（`/猜人物`），直接开局。
  游戏进行中，消息先交给这局游戏（裁判先行：每问先请求一次裁判，猜人物的裁判要查原文时再调几次工具）；裁判判为"非游戏"的话（问玩法、闲聊、想结束、问别的历史问题）
  交给问答 agent 兜底，它的 system prompt 附上正在玩的游戏和玩法，但不知道谜底。退出、放弃 / 揭晓、提示、提交答案、帮助这几个命令
  由 `rag/skills.Router` 统一处理。游戏对象不依赖界面，网页（`app/chat.py`）、命令行和测试都直接调它。
- **谜底只在代码里**：聊天里的模型不知道谜底。裁判是另开的一段对话，看不到聊天记录；一局从头到尾是同一段对话，前面的问答（猜人物还有玩家猜错的名字）都留着，裁判据此前后一致；谜底（海龟汤是汤底）
  和出处原文预先给裁判，猜人物的裁判问到资料以外的事才用工具查。裁判只答结论：是非题答是 / 不是，二选一答选项，原文没写的答"没有记载"，句末是"吗"的问题即使有"或者"也按是非题答（符合任何一项就是），用"还是"连接的才是二选一；问题有两种以上理解且答案不同时，在括号里注明按哪种理解，
  不提供问题以外的信息。
  代码不预先拦问题，唯一的代码检查是 `rag/soup.leaks`：回答里出现谜底的名字或称呼就换成一句"不能说"。玩家猜名字时由代码比对人名和称呼，
  不交给模型判断。
- **随机出题**（猜人物）：先统计别名表里每个人在全书正文块里出现的块数（多人共用的称呼，如"都亭侯"，不用来认人），按块数的 0.5 次方
  加权挑人，再从他出现的块里随机取一块：名人稍多但不独占（模拟 2 万局，曹操约 1.7%）。挑人用代码而不交给模型，因为模型总偏向最有名的人。
  别名表里收了但不是三国时代的人（如孔子）不出题。裁判预载本传首段和抽到的那一块。
- **Agent 来猜**（猜人物的另一种玩法，玩家出题）：整局是同一段对话，Agent 可以用检索工具查原文。每轮跑完 agent 循环后删掉循环追加的
  developer 提醒（如"工具调用次数已经用完"），否则模型会以为之后再也不能查。一问超时时把对话恢复到这一问之前，请玩家再说一句重试。
