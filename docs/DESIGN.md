# 设计说明

## 流水线

```
离线（数据准备）
  维基文库 wikitext ── ingest.fetch_wikisource（按 revid）
    → ingest.sanguozhi：解析正文与裴注，套用 patches.yaml，得到段落 + 裴注（源 id 如 01-0004、01-0004n1）
    → rag.chunk：切块（正文、裴注各自成块，裴注指回所注正文）
    → 白话译文（逐段/逐条，按源 id 对齐）→ ingest.trans_chunks：白话检索切块
    → rag.dense：bge-m3 向量缓存；rag.bm25：字 bigram 倒排
    → 别名表 data/aliases.json、年号表 data/eras.json（每条带出处）

在线（回答一个问题）
  用户问题
    → agent 循环（OpenAI 标准 tools）：模型自己决定调用
         search(query, book?, part?)  白话 hybrid 检索（BM25 + dense，RRF 融合；查询里的人名按别名表另加一路扩展查询；可限定哪一书、正文或裴注）
         read(chunk_id, …)    读前后文；读正文时附上它的裴注，读裴注时附上它注的正文
         who(name)            别名表查人：指谁、有几个同名、其他称呼
         era(era, year, …)    年号第几年 → 公元年
       轮数有上限：最后一轮不传 tools，要求直接作答
    → 作答后的代码检查：坏回答（截断、只有工具标记）重答一次；按资料逐句自查一遍；
       「」里的引文逐字核对原文，对不上的回给模型改一次，改后仍对不上的标为未通过核验；
       引文只标了一个编号、且看过的资料里恰好只有一块含这段文字时，代码改正编号
    → 回答（带资料编号和出处）。回答怎么分事实 / 推断 / 背景是 system prompt 的要求；代码只核对引文，
       不保证每个事实都有出处
```

## 关键决定及理由

| 决定 | 理由 |
|---|---|
| LLM 只走 OpenAI 兼容接口，模型固定为 DeepSeek V4.1 Flash（经 OpenRouter，思考 low） | 留出题上的表现见 README.zh-CN.md "回答效果"；固定一个模型，prompt 和评测数字才有意义。接口仍是标准的，代码里不绑定厂商 SDK |
| Embedding 用本地开源模型（bge-m3）并写死默认值 | 索引与 embedding 绑定；本地模型免 key、可复现 |
| 混合检索而非纯向量 | 人名、地名、官职是精确的词，纯向量会混淆曹操/曹丕/曹植 |
| 入库和查询都做繁→简，走同一套 `rag/normalize.py` | 原文是繁体，提问多为简体；两边不一致就对不上 |
| 别名表只用于查询侧扩展，不改索引 | 史书里称谓随卷而变（太祖、曹公、魏武），问"曹操"要能找到写"魏太祖"的段落；同名的人（几个马忠）不扩展。译文称谓忠于原文后，问"曹操""刘备"直接搜就搜不到。扩展后的查询另加一路融合，而不是替换原查询：替换会把原来排第一的块挤下去 |
| 裴注独立成块，用 parent 指回所注段落 | 1776 条裴注中 60 条超过 1000 字，最长一条 10209 字，并进正文会把块撑大，也分不清陈寿与裴注所引；读裴注时可以把所注正文一起交给模型 |
| 离线把全书译成白话，作为检索用的附加索引 | 一次解决三件事：白话提问对文言用词（去世/薨）、年号只写"七年"、后文只写名或字（"策""宫"）。译文单独建索引，不拼进原文块。**原文仍是依据**：展示和引文逐字校验用原文，prompt 要求引文只引原文、不引译文。48 道检索题上（BM25 + 向量 + 别名扩展，宽松口径）hit@10 从搜原文的 0.69 升到搜白话的 0.81，见 README.zh-CN.md "检索效果" |
| 译文称谓忠于原文，只做现代化 | 太祖 → 魏太祖、權 → 孙权，先主照写；"谁是谁"交给别名表，不在译文里替换人名 |
| 年号换算由代码查表，不让模型凭记忆 | 建兴、甘露等同名年号蜀/吴/魏各不同；年号表从原文统计，并用参考表交叉核对 |
| 查询端去掉白话问句词（`rag/bm25.py` 的 QUESTION_WORDS） | 白话问句词在文言里很稀有（"是谁"全书 3 处），idf 反而很高，会把无关短文档顶上来。词表是照着检索评测题挑的，所以这套题算开发集 |
| 评测 gold 标源 id（段落 id / 裴注 id），不标 chunk id | 换切块策略 chunk id 会变，源 id 不变；同一套题可比较不同切法 |
| 搜什么、读什么由模型用工具决定，代码不预检索 | 模型能按资料里出现的人名、年号继续查（读前后文、查同名者），这是固定 k 块的 RAG 做不到的 |
| search 可以限定哪一书（魏 / 蜀 / 吴）和正文 / 裴注，筛选在每一路检索排名之前做 | 冷门人物常常只在某一卷的裴注里出现一次，全书检索时会被魏书、蜀书里更相关的段落挤出前几名；先取全书前 k 名再过滤也不行，目标块可能根本不在前 k 名里。只在模型已经确定范围时才填，不填就搜全书 |
| 给模型的工具优先选"不需要知识也能用"的 | 读前后文、读裴注所注正文、别名表查人、年号换算，都不依赖模型的史学知识 |
| 轮数上限由代码保证（最后一轮不传 tools） | 实测 `tool_choice="none"` 会被部分模型无视 |
| 作答后由代码做检查（自查、引文核对） | 判卷发现的主要错误是补了资料以外的背景、旁证张冠李戴、引文记错字；自查针对前两种，引文核对针对后一种。引文核对是确定性的代码检查，自查仍是一次模型请求，不保证改对 |
| 向量检索用 numpy 暴力算余弦，不用向量数据库 | 原文、白话两套各 4365 块，1024 维 float32 只有几十 MB，一次矩阵乘法毫秒级 |
| 仓库里只放白文，标点版由使用者下载 | 原文是公有领域，但维基文库录入的断句标点沿用中华书局点校本；`ingest.use_wikisource` 按 revid 下载，结果可复现 |

## 切块

切块的数据依据（`uv run python -m eval.length_stats` 可复现）：

- 正文段 2240 个：中位数 149 字，90% 分位 395，最长 2697；360 段不足 50 字，17 段超过 1000 字。
- 裴注 1776 条：中位数 112 字，90% 分位 496，最长 10209（卷02 獻帝傳 禅代众事）；60 条超过 1000 字。短注多是音注（如"橫音光"）。
- 按 。！？ 切句，最长的一句 398 字，所以 `max_len >= 400` 时不会遇到放不下的单句。
- 156 个段/注不以句末标点结尾，多是以"曰："结尾引出下一段（如 14-0043"曄議曰："）；也有"帝不听。"（22-0013）这种回应上一段的短段。
- 49 个段/注的 text 里含换行（来自多行的 quote 模板）。
- search 与 text 只差年号后的" NNN年"，句末标点完全一致（已全量核对），所以两者能用同一套句子边界切开。

## BM25

`rag/bm25.py` 按字 bigram 建倒排表（词 → {文档序号: 次数}），查询 q 对文档 d 的分数：

```
score(q, d) = Σ_{t ∈ q} idf(t) · tf · (k1 + 1) / (tf + k1 · (1 − b + b · dl / avgdl))
idf(t)      = ln(1 + (N − df + 0.5) / (df + 0.5))
```

tf 是词 t 在 d 里的次数，dl 是 d 的词数，avgdl 是平均词数，N 是文档总数，df 是含 t 的文档数。
k1 = 1.2（tf 饱和速度），b = 0.75（长度归一的程度）。idf 取 Lucene 的加 1 版本：原始 BM25 的 idf 在 df 超过一半时为负，
"之""曰"开头这类几乎每块都有的 bigram 会倒扣分。

## 话题限制

只靠 system prompt 要求模型只回答三国历史问题（演义情节不拒答，而是说明正史怎么记载），代码不强制。没有检索阈值或分类器闸门；
公网部署时可以考虑另加（见 DEPLOY.md）。

## 评测

大模型的训练语料里本来就有大量三国内容，只看"答对没有"分不清是检索的功劳还是模型的记忆，所以分层看：

1. **检索层（不经过 LLM）**：每题标 gold 源 id（`eval/retrieval.jsonl`），看 hit@k / MRR。选 embedding、调切块、决定用不用白话译文都靠这层。
2. **回答层**：agent 跑题，由大模型按判卷规则对照原文判对错（任何事实错误算错，列举题少列算部分）。另有一套出题时没参与过 prompt 调整的留出题，用来看泛化。

另加一个与 LLM 无关的检查：回答里引用的原文要能在模型看过的 chunk 里逐字找到；找不到的回给模型改一次，仍找不到的标为未通过核验
（可能记错字，也可能是异体字）。
